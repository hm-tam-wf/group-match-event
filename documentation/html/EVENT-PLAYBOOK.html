Bước 1, 3, 4 do người phụ trách làm trên trang admin, song song với Bước 2 được. Riêng việc chọn skin mới ở Bước 3 phải đợi code lên production. Bước 2 do người làm code thực hiện; người có quyền Firebase deploy.

Nguyên tắc

  • Một bộ code dùng cho mọi sự kiện; mỗi sự kiện là một bộ dữ liệu riêng, gọi bằng ID.
  • Làm được trên trang admin thì không sửa code.
  • Phải sửa code thì thêm mới, không sửa đè: skin mới nằm trong thư mục riêng; tính năng mới là tuỳ chọn, sự kiện không bật thì chạy y như cũ.
  • Code chỉ đi một đường: nhánh riêng → test → master (staging) → production.
  • Repo công khai: không commit họ tên thật, file nhân sự, khoá service account.

1

Tạo sự kiện

Trang admin
  1. Admin → Sự kiện → Tạo sự kiện, hoặc Nhân bản sự kiện gần giống nhất (chép cấu hình và hồ sơ; tuỳ chọn chép danh sách cho phép, trang thông tin; không chép đăng ký).
  2. Đặt ID: chữ thường, số, gạch ngang. ID nằm trong link riêng, đặt rồi đừng đổi.
  3. Tab Thiết lập: thông tin chung, đội, thời gian (giờ Việt Nam), chống trùng và danh sách cho phép, ô người đăng ký điền. Nên đặt cả giờ đóng (lý do ở Bước 8).
  4. Lưu. Chưa bấm Mở.

Nhân bản chép cả giờ mở và đóng của sự kiện cũ: nhớ sửa lại phần Thời gian.

2

Làm phần code

Chỉ khi cần

2.1 Tạo nhánh riêng

git switch master
git pull
git switch -c event/<id>

Không sửa thẳng master, không làm tiếp trên nhánh của sự kiện cũ.

2.2 Skin mới (giao diện khác)

<theme> là theme nền đang dùng (hiện là tech), <skin> là tên skin mới.

  1. Tạo thư mục fe/themes/<theme>/variants/<skin>/:
    • <skin>.css: mọi selector bắt đầu bằng [data-theme="<theme>"][data-variant="<skin>"]. Muốn khác hẳn thì đè lại token màu, nền, font của theme nền.
    • strings.js: gọi registerVariantCopy("<skin>", { vi: {…}, en: {…} }) để đổi chữ (không sửa STRINGS gốc).
    • img/: ảnh của skin.
  2. Thêm 1 dòng vào AVAILABLE_VARIANTS trong fe/js/config/config.js ({ id, label, theme, defaultLang }). Trang admin lấy danh sách skin từ đây.
  3. Nạp file của skin:
    • CSS vào fe/index.html và fe/home.html.
    • strings.js vào fe/index.html (sau themes/<theme>/strings.js, trước js/config/profile.js) và fe/admin.html.
  4. Lưu ý:
    • Logo vẽ bằng CSS: thêm :not([data-brand="custom"]) để sự kiện khai logo riêng vẫn đổi được.
    • Tiêu đề chữ gradient có dấu chồng (Ố, Ấ, Ề…) dễ mất dấu: thêm padding-top cho h1 trong skin.

2.3 Tính năng mới, sửa phần dùng chung

  • Thêm thành tuỳ chọn trong cấu hình hoặc hồ sơ sự kiện; thiếu tuỳ chọn thì giữ hành vi cũ, để sự kiện khác không đổi.
  • Đổi cách ghi dữ liệu: sửa backend/firestore.rules và test rules.
  • Loại mục mới cho trang thông tin: fe/js/home/home-schema.js (TYPES), fe/js/home/home-render.js, trình soạn trong admin.
  • Viết test cho phần mới (TESTING.md, mục "Thêm case mới").

2.4 Xem trước ở máy

npx serve fe
  • Mở http://localhost:3000/?e=<id>&variant=<skin>&lang=vi. ?variant= và ?lang= chỉ ép tạm để xem, chưa ghi gì vào hồ sơ. Trang thông tin: home.html?e=<id>&variant=<skin>.
  • Kiểm ở bề ngang điện thoại (360 đến 390px) và máy tính: màn chờ, màn chào, form, lưới đội, popup xác nhận, màn đã tham gia, đếm ngược.

2.5 Test

npm test

Cần Node, Java 21+, Chrome hoặc Edge (TESTING.md). Push nhánh và mở Pull Request: CI chạy lại toàn bộ test.

2.6 Đưa vào master (staging)

Merge khi CI xanh. Vài phút sau staging chạy code mới: kiểm <staging>/?e=<id>&variant=<skin>.

2.7 Deploy production

Người có quyền Firebase của project chạy. Mỗi site: deploy ra preview channel → mở link preview CLI in ra, thêm ?e=<id>, chỉ xem (không đăng ký) → clone đúng bản vừa xem lên live. <tên> là tên kênh tạm, vd ev-<id>.

# Trang sự kiện
firebase hosting:channel:deploy <tên> --only pickyourgroup --expires 1h --project icon-picker
firebase hosting:clone pickyourgroup:<tên> pickyourgroup:live --project icon-picker
# Trang admin (cần khi có skin mới, vì danh sách skin của admin nằm trong code)
firebase hosting:channel:deploy <tên> --only pickyourgroup-admin --expires 1h --project icon-picker
firebase hosting:clone pickyourgroup-admin:<tên> pickyourgroup-admin:live --project icon-picker
# Rules (chỉ khi có sửa)
npm run deploy:rules
  • Deploy trang sự kiện trước, trang admin sau.
  • Rules và code đi cùng nhau: deploy lúc không có sự kiện đang chạy; rollback thì rollback cả hai.
  • Khi đã bật deploy theo tag (DEPLOY.md): thay các lệnh trên bằng push tag vX.Y.Z.

Xong sớm hơn giờ mở ít nhất 1 giờ: trang sự kiện gửi kèm Cache-Control: max-age=3600, trình duyệt có thể giữ bản cũ tới 1 giờ (staging: 10 phút).

3

Giao diện, trang thông tin

Trang admin
  1. Sự kiện → Sửa → tab Nhận diện: giao diện, ngôn ngữ, logo, nút Huỷ / Quay lại, chữ trên trang, thời gian màn chào → Lưu & xem trước.
  2. Có trang thông tin: menu Trang thông tin → chọn sự kiện → soạn từng mục, hoặc Nạp Excel / JSON → Lưu → Xem trang. Rồi ở tab Nhận diện, chọn nút Huỷ "Về trang home của sự kiện".
  3. Sự kiện tạo mới (không nhân bản) mang hồ sơ mặc định trong code: luôn mở tab Nhận diện kiểm lại.
4

Nạp người tham gia, đội

Trang admin

Chỉ khi bật danh sách cho phép ở Bước 1.

  1. Danh sách cho phép → chọn sự kiện → Tải file mẫu (sinh theo sự kiện, có sheet Hướng dẫn).
  2. Điền sheet Nhân sự (người) và sheet Phòng (đội). Có sheet Phòng thì thay toàn bộ danh sách đội; không muốn đổi đội thì xoá sheet đó.
  3. Chọn file → xem trước, sửa hết lỗi từng dòng → Xoá cũ & nạp mới (lần đầu) hoặc Nạp thêm (bổ sung). Muốn xếp đội sẵn: điền cột Phòng và tích Xếp sẵn.
  4. File thật để ngoài git (btc-data/ đã được ignore); repo chỉ giữ file mẫu tên giả.
5

Chạy thử

Điện thoại + admin
  1. Mở link riêng <trang sự kiện>/?e=<id> trên điện thoại.
  2. Đăng ký thử vài trường hợp: người hợp lệ, người không có trong danh sách, đội đầy, đội bị khoá theo luật của sự kiện.
  3. Giờ mở ở tương lai thì trang chỉ hiện đếm ngược: tạm để trống giờ mở, thử xong đặt lại.
  4. Thử xong: Sự kiện → Xóa dữ liệu (gõ lại ID). Danh sách cho phép được giữ.
6

Mở sự kiện, gửi link

Trang admin
  1. Sự kiện → Mở. Trang admin tự kiểm trước: giờ đóng đã qua, danh sách cho phép trống, thiếu ô name, ô kiểm trùng không tồn tại, chưa có đội thì chưa cho mở.
  2. Chỉ một sự kiện ở trạng thái Mở: Mở sự kiện mới là thay sự kiện cũ trên link gốc.
  3. Gửi link gốc (theo sự kiện đang Mở) hoặc link riêng ?e=<id> (luôn đúng sự kiện này). Trang thông tin: <trang sự kiện>/home.html?e=<id>.
7

Theo dõi khi diễn ra

Trang admin
  • Tổng quan: sĩ số, đăng ký mới nhất, thẻ Mức dùng Firestore.
  • Sửa 1 người trong danh sách: trang Danh sách cho phép. Người đã vào đội: trang Đăng ký → nút ⋯ (Chuyển phòng, Gỡ khỏi phòng, Bỏ chặn, Xoá đăng ký).
  • Đổi đội, sĩ số, danh sách khi đang chạy: người tham gia phải tải lại trang mới thấy. Không đổi hay xoá đội đã có người.
  • Không deploy code khi sự kiện đang chạy, trừ sửa lỗi gấp (vẫn qua preview channel).
8

Kết thúc, dọn dẹp

Trang admin
  1. Sự kiện → Kết thúc: gỡ sự kiện khỏi link gốc.
  2. Xuất kết quả: Đăng ký → chọn sự kiện → Xuất Excel (hoặc script, EXPORT.md).
  3. File thật của người phụ trách: giữ ngoài git, xoá khi hết cần.
  4. Xoá hẳn sự kiện (tuỳ chọn): Xóa dữ liệu → Xóa sự kiện (xoá cả danh sách cho phép).
  5. Giữ skin, code mới để sự kiện sau chọn lại. Lỗi hay bài học mới: ghi vào tài liệu.

Link riêng ?e=<id> vẫn nhận đăng ký tới giờ đóng, kể cả sau khi bấm Kết thúc. Chưa đặt giờ đóng thì sửa giờ đóng về hiện tại.

Khi bản mới bị lỗi

  • Trang sự kiện, trang admin: Firebase Console → Hosting → chọn site → Release history → bản trước → Rollback.
  • Rules: Firebase Console → Firestore → Rules → lịch sử phiên bản → khôi phục bản trước. Rules đi kèm code thì rollback cả hai.
  • Cấu hình sự kiện sai: sửa lại trên trang admin, không cần deploy.
