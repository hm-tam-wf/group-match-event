Admin Pick group

Bật thẻ Mức dùng Firestore

Hướng dẫn từng bước cho Owner của project Google Cloud icon-picker. Làm xong, cuối trang Tổng quan của admin hiện số đọc, ghi, xoá thật của cả project.

  • Khoảng 10 phút
  • Làm 1 lần
  • Tài khoản Owner
  • Không cần server

Thẻ hiện gì

  • Lượt đọc / ghi / xoá Firestore hôm nay so với quota miễn phí (50.000 / 20.000 / 20.000 mỗi ngày) và đếm ngược tới giờ reset.
  • Biểu đồ lượt đọc 7 ngày quota gần nhất và hôm nay, kèm bảng số liệu.
  • Gói Spark (miễn phí, 0 ₫) hay Blaze (trả theo mức dùng, ước tính chi phí phần vượt quota).

Ngày quota tính theo giờ Pacific: reset lúc 00:00 giờ Pacific, tức 15:00 giờ VN (14:00 khi Mỹ theo giờ mùa hè, khoảng giữa tháng 3 đến đầu tháng 11).

Bấm Kết nối Google trên thẻ thì trang nhận một token chỉ đọc, chỉ giữ trong tab, tự hết hạn sau khoảng 1 giờ. Không đụng đăng nhập admin, không ghi gì vào Firestore, mở trang admin không gọi Google.

Client ID không phải bí mật: chỉ chạy trên origin đã khai báo, với tài khoản được phép, và chỉ xem được project mà tài khoản đó có quyền.

Chuẩn bị

  • Đăng nhập Google bằng tài khoản Owner của project icon-picker. Thường là tài khoản Firebase CLI đang dùng: chạy firebase login:list để xem.
  • Trang báo không có quyền hoặc không thấy project thì đổi tài khoản (ảnh đại diện góc phải trên).
  • Các link dưới đã chọn sẵn project và thêm hl=en để giao diện tiếng Anh, khớp tên nút trong hướng dẫn.
1

Bật API

2 phút
  1. Mở Cloud Monitoring API → bấm Enable. Thấy nút Manage nghĩa là đã bật sẵn.
  2. Tuỳ chọn Mở Cloud Billing API → Enable, để thẻ biết gói Spark hay Blaze. Không cần thì xem Bỏ qua billing.
  3. Trang báo cần billing account thì dừng lại, ghi nguyên văn thông báo.
2

Màn hình đồng ý OAuth

3 phút
  1. Mở Google Auth Platform → Get started. Không thấy nút này nghĩa là đã cấu hình từ trước: nhảy tới mục 5.
  2. App Information: App name Pick group admin, User support email chọn email của bạn → Next.
  3. Audience: chọn Internal nếu bấm được (project thuộc Google Workspace của công ty, khỏi thêm Test users); không thì External → Next.
  4. Contact Information: nhập email của bạn → Next → tick I agree to the Google API Services: User Data Policy → Continue → Create.
  5. External Menu trái Audience → mục Test users → + Add users → nhập email Google của những người sẽ xem thẻ → Save. Giữ trạng thái Testing (không cần Google xác minh, tối đa 100 người), không bấm Publish app.
  6. Menu trái Data Access → Add or remove scopes → kéo xuống ô Manually add scopes, dán 2 dòng: 
    https://www.googleapis.com/auth/monitoring.read
https://www.googleapis.com/auth/cloud-billing.readonly
    → Add to table → Update → về trang Data Access bấm Save. Có cảnh báo "cần xác minh" thì bỏ qua (app đang Testing). Bỏ qua billing thì chỉ dán dòng đầu.
3

Tạo OAuth Client ID

2 phút
  1. Mở Clients → + Create client.
  2. Application type: Web application. Name: admin usage.
  3. Mục Authorized JavaScript origins → + Add URI → dán (không có / cuối): 
    https://pickyourgroup-admin.web.app
    Có dùng domain https://pickyourgroup-admin.firebaseapp.com thì thêm dòng thứ hai.
  4. Để trống Authorized redirect URIs (đừng điền origin vào đây). Có ô Use this client for an AI-powered agent thì không tick.
  5. Create → copy Client ID (dạng 123456789-abc….apps.googleusercontent.com). Không cần Client secret.
  6. Kiểm nhanh: dãy số đầu Client ID (trước dấu -) phải trùng messagingSenderId trong fe/js/config/firebase-config.js. Khác nghĩa là đã tạo nhầm project.

Google ghi chú: thiết lập client có thể mất 5 phút đến vài giờ mới có hiệu lực. Lần bật đầu tiên của project này mất khoảng 15 phút; trong lúc chờ, cửa sổ Google báo Lỗi 401: invalid_client kèm "no registered origin". Cứ đợi rồi thử lại, hoặc kiểm origin.

4

Quyền xem

Chỉ khi cần

Bỏ qua nếu người xem là Owner, Editor hoặc Viewer của project. Người khác:

  1. Mở IAM → Grant access → nhập email Google của họ.
  2. Vai trò Monitoring Viewer, thêm Browser để thẻ đọc được trạng thái billing → Save.
  3. App External thì thêm họ vào Test users (bước 2, mục 5).
5

Dán Client ID và deploy

Người deploy làm
  1. Dán vào fe/js/admin/usage-config.js. Client ID không phải bí mật, commit được. 
    window.ADMIN_USAGE_CONFIG = {
  oauthClientId: "123456789-abc....apps.googleusercontent.com"
};
  2. Deploy site admin: 
    firebase deploy --only hosting:pickyourgroup-admin
    Muốn kiểm trước rồi mới lên live: 
    firebase hosting:channel:deploy <tên> --only pickyourgroup-admin --expires 1h
firebase hosting:clone pickyourgroup-admin:<tên> pickyourgroup-admin:live
    Preview channel có origin khác nên không bấm Kết nối Google được ở đó; chỉ kiểm trang tải được và thẻ hiện nút Kết nối.
6

Thử

1 phút
  1. Mở pickyourgroup-admin.web.app → đăng nhập admin như mọi khi → Tổng quan → kéo xuống cuối, thẻ Mức dùng Firestore → Kết nối Google.
  2. Chọn tài khoản → màn Google hasn't verified this app → Continue (app của chính bạn, đang Testing; app Internal không có màn này) → tick cả 2 quyền → Continue.
  3. Thẻ hiện số đọc / ghi / xoá và biểu đồ là xong. Nút ↻ trên thẻ để lấy số mới; số liệu Cloud Monitoring trễ vài phút.

Bỏ qua billing

Thẻ vẫn chạy đủ phần đọc / ghi / xoá khi bỏ phần billing; chỉ không biết gói Spark hay Blaze: thẻ hiện "Gói chưa rõ" và dòng chi phí nêu cả 2 khả năng. Chọn 1 trong 3 cách:

CáchLàm gìThẻ hiện
Không bật Cloud Billing APIBỏ bước 1, mục 2"Chưa biết gói vì Cloud Billing API chưa bật" kèm link bật
Bỏ tick quyền billing khi kết nốiBước 6, mục 2: chỉ tick quyền Monitoring"Chưa biết gói vì chưa cấp quyền xem billing khi kết nối"
Tắt hẳnThêm checkBilling: false vào usage-config.js rồi deployKhông xin quyền billing nữa, cửa sổ Google chỉ hỏi 1 quyền
 
window.ADMIN_USAGE_CONFIG = {
  oauthClientId: "…",
  checkBilling: false
};

Tắt hẳn thì cũng bỏ dòng cloud-billing.readonly ở bước 2 (mục 6) và quyền Browser ở bước 4.

Kiểm origin đã có hiệu lực chưa

Không cần đăng nhập admin. Dán Client ID (giá trị trong usage-config.js), bấm Chép link, rồi mở link trong cửa sổ ẩn danh. Thấy trang đăng nhập Google nghĩa là origin đã nhận; thấy trang lỗi "Access blocked" / "register the JavaScript origin" nghĩa là chưa.

Mở trong tab thường (đang đăng nhập Google) thì thấy màn chọn tài khoản cũng nghĩa là origin đã nhận. Link mẫu, thay CLIENT_ID:

https://accounts.google.com/o/oauth2/v2/auth?gsiwebsdk=3&client_id=CLIENT_ID&scope=https%3A%2F%2Fwww.googleapis.com%2Fauth%2Fmonitoring.read&redirect_uri=storagerelay%3A%2F%2Fhttps%2Fpickyourgroup-admin.web.app%3Fid%3Dauth1&prompt=&response_type=token&include_granted_scopes=true&hl=en

Ghi chú số liệu

  • Số lấy từ metric firestore.googleapis.com/document/{read,write,delete}_count (giống tab Usage của Firebase console), gần đúng số tính phí; trang Usage and billing là nguồn chính thức.
  • Chi phí "ước tính" chỉ có nghĩa khi project ở Blaze (icon-picker đang ở Blaze): cộng theo ngày (số vượt quota ÷ 100.000 × giá). Giá mặc định là mức trần phổ biến ($0.06 / $0.18 / $0.02 cho 100.000 đọc / ghi / xoá), chưa xác minh cho vùng asia-southeast1: sửa pricePer100k trong usage-config.js theo bảng giá Firestore (chọn Singapore). Chưa gồm lưu trữ, băng thông.
  • Spark không bao giờ tính tiền: vượt quota thì Firestore từ chối yêu cầu tới giờ reset (trang sự kiện có thể lỗi); thẻ cảnh báo khi vượt.
  • Đọc metric qua API tính theo số time series trả về, 1 triệu đầu miễn phí mỗi billing account; mỗi lần làm mới khoảng 6 time series, coi như 0.
